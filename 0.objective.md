# Objective: PrimeOrganism-0

## Goal
Find the **largest probable prime number** using the **minimum possible time and computation**.

## Fitness Function
```
fitness = best_bits / (total_attempts × elapsed_time)
```
Higher is better. The system must **maximize bit-size** of the discovered prime while **minimizing** both the number of attempts and wall-clock time.

## Constraints
- **Time budget**: 5 seconds per organism lifetime (`time_limit_sec=5.0`)
- **Algorithm**: Miller-Rabin probabilistic primality test
- **Starting point**: 16-bit candidates, doubling each generation
- **Candidate shape**: random odd integers with exact target bit-length

## What "Useful Adaptation" Means Here
Every evolutionary step must improve at least one of:
1. **Discovery speed** — find a prime of the same size in fewer attempts
2. **Ceiling growth** — reach a larger bit-size within the same time budget
3. **Efficiency** — reduce CPU cycles per primality test without sacrificing accuracy

## What "Cost-bounded" Means Here
- **Computational cost**: keep Miller-Rabin rounds adaptive; don't test with more rounds than needed
- **Code complexity**: changes must remain simple enough to be verifiable
- **Risk**: no modification should break the primality test correctness or introduce infinite loops

## Evolution Direction (Suggestions for Apostles)
- Improve candidate generation (e.g., sieve pre-filtering, avoiding small-factor candidates)
- Optimize growth strategy (adaptive bit-size scaling instead of fixed ×2)
- Tune Miller-Rabin round count dynamically based on bit-size
- Parallelize search within the time budget
- Improve fitness function to better guide future generations
