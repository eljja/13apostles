Primorial-Residue Wheel Candidate Synthesizer (PRWCS)

### Core Change

This causes a high rate of composite candidate generation, bloating the `total_attempts` metric (the denominator of the fitness function) with wasteful trials that fail on basic factors like 3, 5, 7, and 11. 

The **Primorial-Residue Wheel Candidate Synthesizer (PRWCS)** shifts the sieve logic directly into the *candidate generation phase*. We define a primorial $P_5 = 2 \times 3 \times 5 \times 7 \times 11 = 2310$. At module startup, we dynamically compute and cache the complete set of $\phi(2310) = 480$ coprime residues to 2310 as an immutable tuple.

We refactor `make_candidate()` to construct candidates structurally:
1. Select a random coprime residue $R$ from the cached 480-element tuple.
2. Calculate the valid multiplier range $[M_{min}, M_{max}]$ such that $N = M \times 2310 + R$ is guaranteed to fall exactly within the range $[2^{\text{bit\_size}-1}, 2^{\text{bit\_size}} - 1]$.
3. Pick a random integer $M$ in that range and return $N$.

```python
# Startup Initialization
def _generate_wheel_residues():
    return tuple(i for i in range(1, 2310) if i % 2 != 0 and i % 3 != 0 and i % 5 != 0 and i % 7 != 0 and i % 11 != 0)

WHEEL_RESIDUES_2310 = _generate_wheel_residues() # Exactly 480 elements
WHEEL_MODULUS = 2310

# Inside PrimeOrganism:
def make_candidate(self):
    """
    Synthesize a candidate guaranteed to be coprime to 2, 3, 5, 7, and 11.
    """
    if self.bit_size < 12: # Fallback for extremely small sizes
        n = random.getrandbits(self.bit_size) | 1 | (1 << (self.bit_size - 1))
        return n
        
    R = random.choice(WHEEL_RESIDUES_2310)
    
    # Calculate the bounds for multiplier M to guarantee exact bit-length
    low_bound = (1 << (self.bit_size - 1)) - R
    high_bound = (1 << self.bit_size) - 1 - R
    
    m_min = (low_bound + WHEEL_MODULUS - 1) // WHEEL_MODULUS
    m_max = high_bound // WHEEL_MODULUS
    
    M = random.randint(m_min, m_max)
    return M * WHEEL_MODULUS + R
